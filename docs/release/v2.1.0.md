# log-io v2.1.0 - Recent Lines and File Permissions

**Date:** 2026-10-23
**Compare:** `v2.0.0...v2.1.0`

## Headline

An additive release with two things a service needs when it crashes or
runs on a shared machine: the last log lines kept in memory for a crash
report, and log files that other users cannot read. Nothing that worked
with 2.0 changes behaviour.

## Added

### `sink::RecentLines`

A ring of the last N formatted lines. Every slot is allocated when the
sink is built, so memory is fixed (`capacity` lines of at most
`line_limit` bytes, 1 KiB by default) and writing a record does not
allocate. A line longer than the limit is cut at the last character
boundary that fits. Lines are formatted from the record the logger
built, so values the logger redacts stay redacted in the ring.

Keep an `Arc` to read it and give the logger a clone:

```rust
use std::sync::Arc;
use log_io::format::LogfmtFormat;
use log_io::sink::RecentLines;
use log_io::Logger;

let recent = Arc::new(RecentLines::new(64, LogfmtFormat::new()));
let logger = Logger::builder()
    .stderr_logfmt()
    .with_sink(Arc::clone(&recent))
    .build();
log_io::info!(logger, "ready");
let last_lines = recent.snapshot(); // oldest first
```

`try_snapshot` and `try_write_to` never wait: when the ring is held (for
example, a panic happened while it was being written on the same
thread) they return without the lines instead of deadlocking. That is
what makes the ring usable from a panic hook.

### File permissions

`FileSink::builder(..).mode(bits)` and `RotatingFile::builder(..).mode(bits)`
set the Unix permission bits of every file the sink creates, such as
`0o600` or `0o640`; for a rotating file that includes each new file
after a rotation. The process umask still applies, and an existing file
keeps its mode. Without `mode` a new file gets `0o666` minus the umask,
exactly as in 2.0. On Windows files inherit their directory's access
control list and the mode has no effect.

## Compatibility

Minor release under Semantic Versioning: new items only, no change to
existing behaviour, no new dependencies, MSRV unchanged (1.85).
