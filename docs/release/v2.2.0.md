# log-io v2.2.0 - Review fixes

**Date:** 2026-11-11 · **Compare:** `v2.1.0...v2.2.0`

Fixes from an independent review. No breaking API change; MSRV
unchanged (1.85); no new dependency.

## Fixed

- logfmt can no longer be made to forge log lines by a lazy value
  (`%x`, `?x`) that renders differently each time: lazy values are
  rendered once, and the text that decided the quoting is the text
  written.
- File sinks no longer follow symbolic links: `FileSink::create` cannot
  truncate, and `FileSink::append` or `RotatingFile` cannot append to, a
  file a planted link points to.
- `NonBlocking` has a byte budget (16 MiB by default) next to its record
  count, so a stalled writer cannot pin gigabytes of large records.

## Added

- `log_io::init_json()`, `init_logfmt()`, `init_human()` and `InitError`.
- `follow_symlinks(bool)` on the file sink builders.
- `max_queued_bytes(bytes)` and `queued_bytes()` on `NonBlocking`.
- `*` wildcards in `redact_key`.

## Changed defaults

- New log files get mode `0o600` on Unix (was `0o666` minus the umask).
  Use `.mode(0o644)` for the earlier behaviour.
- File sinks refuse a symbolic link or non-regular file at the log path.
  Use `.follow_symlinks(true)` for the earlier behaviour.
- `redact_common_secrets` matches patterns (`*password*`, `*token*`,
  `*secret*`, ...), so `db_password` and `X-Auth-Token` are redacted.

Every fix has a regression test.
