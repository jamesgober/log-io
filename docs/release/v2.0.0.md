# log-io v2.0.0 - Durable, Safe Output

**Date:** 2026-10-13
**Compare:** `v1.0.0...v2.0.0`

## Headline

A major release that fixes every finding of the 2026-10-13 library
audit and adds the features 1.x was missing. Records are no longer lost
at exit, request context can no longer leak between async tasks, no
input can inject terminal escapes or forge log lines, and field names
can no longer spoof a record's level or message. On top of that, 2.0
adds a global logger with a flush guard, `format!`-style macros,
`log` and `tracing` bridges, a background writer, a rotating file
writer, redaction, and terminal colour.

Several fixes could only be made with breaking changes (a `!Send`
context guard, `#[non_exhaustive]` enums, an object-safe `Format`
trait, changed output escaping), so this is 2.0.0 rather than 1.1.0.
Upgrade guide: [`docs/MIGRATION.md`](../MIGRATION.md).

The hot path still performs no heap allocation in steady state, now
covered by a permanent counting-allocator test, and the default build
still has zero dependencies and no `unsafe` code.

## What changed since `v1.0.0`

### Breaking - MSRV 1.85, edition 2024

The crate requires Rust 1.85 (was 1.75) and uses edition 2024. The
1.x test suite already needed 1.85 for its dev-dependencies; CI now
builds and tests on 1.85 exactly.

### Breaking - context guards stay on their thread

`ContextGuard` is `!Send` and `!Sync`. In 1.x a guard held across an
`.await` in a multi-threaded runtime could be dropped on another thread,
leaving its field (a tenant or request id) attached to unrelated later
records on the original thread. That is now a compile error. To carry
context into tasks, capture it:

```rust,ignore
let snapshot = log_io::context::capture();
tokio::spawn(snapshot.wrap(async move { handle().await }));
```

`ContextSnapshot::{attach, scope, wrap}` re-install the fields on
whichever thread runs the work; `wrap` does so around every poll, with
any executor.

### Breaking - `Format` is object-safe

`Format::write_record` now takes `&mut dyn fmt::Write`, so
`Box<dyn Format>` and runtime format selection work, as the 1.x docs
claimed. The statically dispatched fast path moved to the provided
method `write_record_generic`, which the built-in formats override and
the sinks call. Closures become formats through `format::from_fn`.

### Breaking - room to grow

`Value`, `Error`, `Metadata` and `Record` are `#[non_exhaustive]`.
`Value` gained `I128`, `U128`, `Bytes`, and lazily formatted `Display`,
`Debug` and `Error` variants (the last renders the source chain).

### Breaking - output is safe for any input

- All three formats escape C0 and C1 controls, DEL, U+2028, U+2029 and
  the bidirectional override and isolate characters. A record is one
  line and cannot drive a terminal, whatever it contains.
- JSON and logfmt write user fields named `timestamp`, `level`,
  `target`, `message`, `file` or `line` as `fields.<name>`.
- The logger removes duplicate keys: call-site fields beat context,
  which beats default fields, an inner context scope shadows an outer
  one, and a repeated call-site key keeps its last value. `level` and
  `fields.level` count as the same key, since both are written as
  `fields.level`.
- Floats use Rust's round-trippable `{:?}` text, so `1.0` stays a float
  and `f64::MAX` is short and parseable.

### Breaking - filters behave like `RUST_LOG`

The most specific rule wins regardless of order (1.x used the first
match). `Filter::parse` rejects empty input (also `","`), empty
targets, targets ending in a separator and targets with whitespace, and
its error names the offending segment.

### New - durable shutdown

- Records at `Level::Error` and above are flushed before the logging
  call returns (`LoggerBuilder::flush_on` changes the level). A
  `NonBlocking` sink with `Overflow::DropNewest` keeps its promise never
  to wait: there the record only queues a flush for the worker.
- `log_io::init(logger)` installs a global logger and returns a
  `FlushGuard` that flushes and shuts down every sink at the end of
  `main`. `Logger::shutdown`, `Logger::flush_guard` and
  `global::shutdown` cover other exit paths.
- `global::install_panic_hook` logs and flushes panics, including under
  `panic = "abort"`. A panic on a `NonBlocking` worker thread is left to
  the previous hook (which prints it), since logging it would wait for
  the panicking thread.
- `FileSink::builder` sets the buffer size (`0` writes through) and
  `sync_on_flush` (fsync).
- Dropping the last `Logger` clone shuts its sinks down and reports
  failures.

The audit's reproduction (a `static` logger with a `FileSink`) wrote a
0-byte file; it now writes all 10 records, including when the process
calls `abort()` after logging them.

### New - macros, global logger, environment filter

```rust,ignore
let _guard = log_io::init(Logger::builder().env_filter("LOG_IO").stdout_json().build())?;
log_io::info!("user {id} logged in from {}", addr, http.status = 200_u16, peer = %addr);
log_io::warn!(target: "billing", "retrying", attempt = 2_u8);
```

Messages are format strings (inline captures and positional
arguments), keys can be dotted or string literals, `%` / `?` record
values through `Display` / `Debug` lazily, and the logger argument is
optional. The filter is checked once, before any argument is evaluated.

### New - sinks

- `sink::NonBlocking`: formats on the caller, writes on a background
  thread; bounded queue with `Overflow::Block` (lossless, default) or
  `Overflow::DropNewest` (counted, never waits on the writer); drains on
  shutdown and writes synchronously afterwards. The writer may log into
  the same sink without deadlocking.
- `sink::RotatingFile`: size and UTC time rotation with retention.
  Closes the handle before renaming (works on Windows). A rotation is
  all or nothing: the active file is moved aside first, the oldest file
  is deleted only once every rename has succeeded, and a failed rename
  undoes the ones before it. A failed rotation therefore never deletes
  or overwrites rotated history; the writer keeps appending to the
  current file and reports the error on the next flush.

### New - integrations

- Feature `log`: `compat::LogBridge` routes the `log` facade into a
  logger, keeping key-values and their types.
- Feature `tracing`: `compat::TracingLayer` writes `tracing` events
  through log-io sinks with enclosing span fields as context.

Both are allocation-free per record in steady state.

### New - redaction and colour

`LoggerBuilder::redact_key` and `redact_common_secrets` replace values
of secret-looking keys (`password`, `token`, `authorization`,
`x-api-key`, ...; case-insensitive, `-` matching `_`, also matching the
last dotted segment) with `[REDACTED]` without ever formatting them. `stdout_human` / `stderr_human` colour the level
column on terminals, honouring `NO_COLOR` and `CLICOLOR_FORCE`.

### Fixed - the rest of the audit

Pushing context from inside a sink no longer panics; a guard dropped in
a sink or during thread teardown no longer leaks or aborts; the
thread-local format buffer shrinks back to 64 KiB after a huge record
(1.x kept 128 MiB after one 64 MiB record); `on_error` sees every
failing sink and a handler that logs cannot recurse forever; RFC 3339
clamps at year 9999 instead of wrapping; `ErrorHandler` is exported;
`cargo test --no-default-features` passes. Every finding has a named
regression test in `tests/regressions.rs`.

### Fixed - found by the pre-release re-audit

An independent re-audit of this release (2026-10-14) found defects in
the new code, fixed before publication, each with a regression test
that failed before the fix:

- `RotatingFile` deleted one rotated file per failed rotation (the
  Windows case of another process holding the active file), so retries
  wiped the whole history. Rotation is now transactional (above).
- With the panic hook installed, a panic on a `NonBlocking` worker hung
  the process and hid the panic message. It now exits normally, prints
  the message, and the sink reports `Error::Closed`.
- Under `Overflow::DropNewest`, one `error!` waited for the whole queue
  to drain: 345 ms behind a 5 ms-per-write writer, now about 1 µs.
- Context held across an `.await` in a future wrapped with
  `ContextSnapshot::wrap` leaked into sibling futures on the same thread
  (`join!`, `LocalSet`); the wrapper now keeps it with its future. The
  docs now say plainly that unwrapped futures on such executors still
  leak, and to wrap them.
- Repeated call-site keys were written twice; `","` silenced all
  logging; `NonBlockingBuilder::build` could panic; redaction missed
  hyphenated header names; `RotatingFile` read the clock on every write
  without a time schedule.

### Changed - documentation tells the truth

The "async-safe sinks" claim, the `&dyn Format` and closure claims, the
rotation advice and the 1.x performance table were wrong and are
corrected. Every Rust example in the README and `docs/API.md` now
compiles and runs as a doctest.

## Performance

Machine: AMD Ryzen 9 9950X3D, Windows 11, rustc 1.95.0, `lto = "thin"`.
The machine was shared with other build jobs, so 1.0.0 and 2.0.0 were
compared with one probe compiled against each version and run
alternately (8 rounds, minimum per case). Full method and criterion
medians in [`BENCH.md`](../../BENCH.md).

### Formatters (ns / record, 5 fields)

| Format | 1.0.0 | 2.0.0 | Change |
|---|---:|---:|---:|
| JSON | 133.2 | 123.0 | -7.7% |
| logfmt | 156.7 | 115.2 | -26.5% |
| human | 199.2 | 196.6 | -1.3% |
| JSON, no fields | 12.5 | 12.2 | -2.4% |

### Pipeline (ns / call, 3 fields unless noted)

| Path | 1.0.0 | 2.0.0 | Change |
|---|---:|---:|---:|
| filtered out | 2.0 | 0.8 | -60% |
| `NullSink` | 7.3 | 8.9 | +1.6 ns |
| JSON writer | 63.2 | 63.8 | +0.9% |
| logfmt writer | 65.4 | 58.3 | -10.9% |
| JSON writer, no fields | 26.4 | 31.6 | +5.2 ns |
| 2 default fields | 94.2 | 91.6 | -2.8% |
| context, 2 fields | 105.8 | 101.2 | -4.3% |
| default config (timestamp + context) | 113.3 | 114.1 | +0.7% |
| `info!` macro, default config | 138.9 | 137.5 | -1.0% |

The +1.6 to +5.2 ns on the two cheapest paths is the fixed cost of the
new per-record work (key de-duplication, error-handler reentrancy
guard, flush-on-level check, dispatch-depth tracking for the panic
hook). It is above the 5% REPS threshold in relative terms on those two
micro-paths; it is accepted because it buys the durability and safety
fixes above, and on records with fields the faster formatters absorb
it.

### Concurrent throughput (ns / record, one shared JSON sink)

| Threads | 1.0.0 | 2.0.0 | Change |
|---:|---:|---:|---:|
| 1 | 62.9 | 64.4 | +2.4% |
| 2 | 45.7 | 40.0 | -12.5% |
| 4 | 32.7 | 24.4 | -25.4% |
| 8 | 71.4 | 26.8 | -62.5% |

Sink mutexes now sit on their own cache lines; in 1.x lock traffic
invalidated data that every logging thread reads.

### Allocation

Zero allocations per record in steady state on every path covered by
`tests/alloc.rs` (default config, all three formats, context, default
fields, redaction, `format!` messages, the `log` bridge, `tracing`
events). Unchanged and documented: more than 16 ambient fields spill to
one heap allocation per record, and creating a context guard allocates.

## Migration

### From `v1.x`

See [`docs/MIGRATION.md`](../MIGRATION.md). The three edits most
programs need:

1. Escape literal braces in macro messages (`{` becomes `{{`).
2. Keep the `FlushGuard` from `log_io::init` (or call
   `Logger::shutdown`) if your logger lives in a `static`.
3. Add a wildcard arm where you `match` on `Value` or `Error`.

Custom formats change one signature
(`write_record(&self, &Record, &mut dyn fmt::Write)`), and code that
moved a `ContextGuard` across threads must use `context::capture()`
instead.

## Stability commitment

- **Patch (`2.0.x`)** - bug fixes, documentation, internal performance
  work, test additions.
- **Minor (`2.x.0`)** - additions: new items, new variants on the
  `#[non_exhaustive]` enums (`Value`, `Error`, `ParseFilterErrorKind`,
  `BuildError`, `Overflow`, `Rotation`, `ColorChoice`), new fields on
  `Metadata` and `Record`, new optional features.
- **Major (`3.0.0`)** - removing or changing a public item, changing
  escaping or existing output keys, raising the MSRV, or adding a
  non-optional dependency.

CI's `semver-checks` job enforces the API part; `REPS.md` section 9
binds the rest.
